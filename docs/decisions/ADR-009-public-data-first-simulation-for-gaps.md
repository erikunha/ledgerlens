# ADR-009: Public data first, simulation only for the gaps

Status: accepted. Date: 2026-11-07.

## Context

The agent investigates data. If all the data is generated by a program of ours, the agent only rediscovers the generator, and the evaluation becomes circular. Not everything exists in a public source: there are no open per-transaction chargeback records, no settlements with fees, and no acquirer exchange-rate markup. Only sources without a key, an account or a login are used.

Two facts guide the decision:

- **Exchange rates.** Frankfurter v2 without a pinned source returned EUR/BRL 5.7379 on 2026-10-05, against 5.5849 from the ECB (checked in this pass), a difference of 2.7 percent, about the size of a markup. An agent that used this value would invent a difference that does not exist.
- **Licenses.** UCI Online Retail II is CC BY 4.0 and downloads without a login. Olist (CC BY-NC-SA, Kaggle login), PaySim (login), SDV (BUSL license) and Gretel (archived) are left out.

## Decision

Real data where it exists, simulation with a fixed seed only for what does not, and everything goes through an event log.

| Layer | Source | Role |
|---|---|---|
| Orders and cancellations | UCI Online Retail II | `transactions` and `refunds` (cancellations are invoices that start with `C`) |
| Reference exchange rates | ECB through Frankfurter v1 (or v2 with `providers=ECB`), cross-checked against BCB PTAX and the ECB Data Portal | `fx_applied` and the exchange-rate tool |
| Business days | the `holidays` library (TARGET and B3 calendars) | settlement dates |
| Card brands | CC BY 4.0 BIN list | `card_brand` |
| Calibration | BCB open Pix statistics | order of magnitude of the dispute rate |
| Simulated (fixed seed, `Faker`) | merchants, chargebacks, settlements and fees, exchange-rate markup, planted anomalies | only what is missing |

Architecture (code in `ledgerlens/sim/`):

- `scripts/fetch_public_data.py` downloads the files into `data/raw/` (outside git) and records the URL, size, SHA-256 and license in `data/sources.lock.json`.
- An adapter turns the public file into neutral records. The simulator fills the gaps and injects named scenarios. Everything becomes events in a single append-only log (`events`).
- A projector builds the read tables from the events. The agent queries only the tables. Rebuilding the project from scratch from the events gives the same result (canonical hash).
- `data/scenarios.json` lists each planted anomaly with the truth (values, ids, expected trajectory). Tests and evaluation read this manifest.
- Each row has `origin` (`public`, `synthetic` or `scenario:Sxx`). The documentation reports the real share.
- Offline: a derived, time-shifted sample is versioned in `data/sample/`, with `NOTICE` for the attribution (CC BY 4.0 allows redistribution with attribution). Without the sample, the synthetic generator with a fixed seed applies. `uv run ledgerlens-sim --days 90 --seed 42 --scenarios all` recreates `data/ledger.db` and `data/scenarios.json`.
- A local, read-only internal API serves the same SQLite file (internal service versus external API, by kind of use). If the schedule gets tight, it is the first item cut.

## Alternatives considered

- **Fully synthetic.** Easy and reproducible, but circular: every number comes from our generator, and the agent only proves that it reads its own generator.
- **Fully public.** No open source has exchange-rate markup, chargebacks with deadlines or settlements with fees. The scenarios that show the agent's value would not exist.
- **Kaggle datasets (Olist, PaySim).** They need a login, and Olist has a non-commercial, share-alike license, which would tie up the repository.
- **Commercial or archived generators (SDV, Gretel).** The license or the state of the project is unsuitable.

## Consequences

- The evaluation separates what is real from what is simulated, row by row (`origin`) and by table.
- UCI prices are in pounds. They are converted into the merchant's currency with the ECB rate of the shifted date, and 12 percent of customers are reassigned to Brazil, because the file has almost no Brazilian customers. These transformations are documented in the manifest.
- The original data is from 2009 to 2011 and the dates are shifted to 2026. The exchange rate uses the real rates of the shifted dates.
- The extra work (fetch, adapter, projector, manifest, internal API) is the cost of an evaluation that is not circular.
- The rate of cancellations tied to sales is measured on the first run and recorded in the manifest (not verified beforehand).
