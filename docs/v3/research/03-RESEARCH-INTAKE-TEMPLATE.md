# Unlimited Vision: New Capability Intake and Due Diligence

New trends never require renumbering existing capability IDs. Add an ID and a separate research note. Record:

1. `research_id`, observed date, source primary URL, date the capability was actually published, uncertainty.
2. Functional promise and target persona, not just framework name.
3. Which strategic lens explains value; who benefits and who bears the risk.
4. Existing LedgerLens capability it extends, whether it can be shown as replay, sandbox or live.
5. Proposed architecture seam, data/model dependencies, policy/secret implications.
6. Minimal falsifiable experiment and independent baseline.
7. Effect on correctness, cost-per-correct, human work, latency, security and comprehension.
8. Dataset provenance, license, model dependencies and reproducibility.
9. Decision to adopt, adapt, postpone, or document a negative result; explicit reason.
10. Source revision, date, verification and last-review timestamp.

A new research idea can stay in the roadmap indefinitely. Publication of the idea never implies it is built. A novel feature may also be implemented as a narrow optional research plugin instead of entering the main support workflow.

Orchestration SDK evolution; MCP and A2A authorization semantics; tracing telemetry standards; local/small models, on-device constraints; multimodal receipts/documents; retrieval and memory security; agent incident forensics; LLM judge calibration; adaptive inference budgets; privacy and synthetic data governance; accessibility of complex agent UIs; developer hiring signals; domain-specific financial agent benchmarks; reliability and long-running durable workflows.
