# Modes, Journeys and Educational UX

## Four mode labels - non-negotiable

- **Recorded replay:** a captured run with its historical input, model, timestamps and tool outputs. It can be paused, scrubbed and inspected. No new inference occurs.
- **Deterministic sandbox:** exact domain logic runs over a branch of fictional data; dynamic narrative may be templated, but not falsely labeled a live LLM answer.
- **Live BYOK:** the visitor explicitly consents to sending sandbox inputs to a selected supported provider and using their key. Show token and cost events, stop button and data destination.
- **Research preview:** diagrams, benchmarks or mockups of unimplemented ideas. Never show as working demo.

## One-minute cold start (recruiter)

Entry → choose 'Why was this refund lower?' → 8-12 meaningful replay steps (not artificial delays) → answer + per-claim check → source linked → 'See what happens if I change the FX rate'. Plain words first, engineer details optional. No account or key.

## Three-minute engineering tour

Entry → S09 prompt injection → inspect malicious ledger note → observe SQL guard / untrusted-data boundary → verifier verdict → branch and rerun with malicious note removed → compare trace → link to guarded source code/tests.

## Deep dive (staff engineer)

Architecture → S01 as tool agent C → compare A/B/C → alter currency/policy on sandbox → decide escalation → open cost-quality-risk frontier → inspect run manifest, nondeterministic variation, security boundary and failure gallery.

## Live BYOK path

Settings → inspect provider destination/cost disclosure → paste key → server creates ephemeral session binding → choose model from tested registry → run selected fictional case → stream trace (provisional) → verifier concludes → compare with baseline → explicitly forget key. No auto-switch to a more costly model without prior consent and budget.

## UX trust failures to avoid

Do not animate fake thinking, call simulation 'AI', remove source limitations from summaries, label model confidence as probability, render a fabricated evidence card, expose keys in pasted example, auto-run paid inference, or imply real transactions are being edited. Every mutating UI action includes sandbox-only badge and reset.
